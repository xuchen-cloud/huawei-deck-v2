# 内容表达与展示逻辑

本文件定义论证方法论：如何从任务目的推导出页面结构、组织证据链、选择叙事弧线并检查单页。阶段流程由调用本文件的 skill 定义；视觉与载体规则只在 `$huawei-deck-build` 阶段加载。

在选择版式前先完成本文件的判断。内容逻辑决定页面结构，视觉只负责降低理解成本。信息传递是首要目标：保留支持理解、判断和行动所需的事实、机制、边界、数据、案例与实施细节；不得为了页面极简而强行压缩内容。

## 目录

1. 规划整套材料
2. 通用论证结构
3. 不同任务的叙事结构
4. 信息筛选与量化
5. 单页组织
6. 精简、密度与阅读顺序

## 1. 规划整套材料

所有材料先完成以下七步，再进入页面设计：

1. **明确任务**：确认材料用于告知、解释、分析、比较、复盘、说服还是推动决策；
2. **明确对象**：确认读者角色、已有认知、关注点、可决策范围和汇报时长；写清读者阅读前状态与阅读后应达到的理解、判断或决策状态；
3. **完整盘点**：整理已有事实、数据、案例、截图、规则、结论、未知项和待验证项，同时识别 Agent 可继续研究的证据与需要人工补充的内部材料；两者可以并行存在，不在此阶段因版面限制过早删减；
4. **形成主线**：写清核心问题、证据展开顺序和期望形成的判断或行动；
5. **选择结构**：根据任务使用问题—原因—方案、目标—结果—差距、范围—机制—边界、统一维度比较或其他合适结构；
6. **建立映射**：将每个主要观点对应到已核验证据、人工待补项或明确推断，将每项建议对应到问题、根因、差距、风险或机会；
7. **选择载体**：最后决定使用表格、图表、流程、架构、截图或文字，不先选版式再填内容。载体选择规则见 `visual-system.md §5`。

### 1.1 先写主线，再写目录

开始制作前，用一句话写清：`本材料要回答什么问题 -> 将按什么顺序提供证据 -> 希望读者形成什么判断或采取什么行动`。

再建立页面级故事板，至少包含：

| 字段 | 要回答的问题 |
|---|---|
| 页面任务 | 这一页在整条论证中承担什么作用？ |
| 主要观点 | 读者看完这一页应确认什么？ |
| 支撑信息 | 哪些数据、事实、截图、案例或对比能证明观点？ |
| 上下承接 | 它回应了前一页什么，又为后一页提出什么？ |
| 行动关联 | 它最终支持哪项建议、目标、计划或决策？ |

仅在标题序列可以独立读成一条完整论证后，才开始页面布局。若连续两页没有清楚的因果、递进、并列或问题—回答关系，应调整顺序或合并重复内容。

### 1.2 根据材料目的选择结构

- **洞察或研究材料**：先明确研究问题，再按证据性质选择结构。行业 -> 友商 -> 自我是分析外部趋势并落到自身差距时的一种可选结构，不是洞察类材料的统一模板。能力洞察、技术机制、政策影响、客户需求等主题应使用各自更合适的顺序。
- **问题解决或提案材料**：前半部分建立问题的重要性，后半部分证明方案有效且可实现。
  - 前半部分：目的与背景 -> 现状与应有状态 -> 关键问题 -> 根因；
  - 后半部分：候选方案 -> 方案选择 -> 目标 -> 时间、责任、资源、预算与风险。
- **工作汇报材料**：目标或计划 -> 完成结果 -> 差距与原因 -> 后续计划和需协调事项。
- **说明材料**：问题或疑问 -> 原因与机制 -> 处理方式或结论 -> 边界和注意事项。

不要把一种结构强行套到所有任务。先判断材料要完成的是告知、解释、分析、比较、复盘、说服还是推动决策，再选择展开方式。若材料只负责分析，不要求提出方案，可以停在影响与待验证事项；若材料用于决策，必须说明推荐项和需要决策者确认的内容。

可使用下表快速选型：

| 任务类型 | 核心问题 | 常用展开关系 |
|---|---|---|
| 工作汇报 | 计划完成得怎样，后续怎么推进？ | 目标/计划 -> 结果 -> 差距与原因 -> 后续动作 |
| 问题解决 | 为什么未达到应有状态，怎样解决？ | 目的 -> As-is/To-be差距 -> 根因 -> 方案 -> 目标 -> 计划 |
| 方案决策 | 多个方案中应该选哪个？ | 约束与评价维度 -> 候选方案 -> 效果/可行性比较 -> 推荐 -> 风险与计划 |
| 能力拆解 | 能力具体做什么，机制和边界是什么？ | 范围 -> 入口/对象 -> 流程与机制 -> 覆盖/未覆盖 -> 价值 |
| 竞品比较 | 在统一维度下差异在哪里？ | 范围与维度 -> 原生对比表 -> 关键差异 -> 形成原因 -> 影响 |
| 趋势研究 | 多项事实共同说明什么变化？ | 研究问题 -> 独立证据 -> 共同机制 -> 影响 -> 应对或验证 |
| 运营复盘 | 指标为何变化，怎样改进？ | 目标与口径 -> 趋势与异常 -> 原因 -> 动作 -> 责任与验收 |
| 机制说明 | 某项规则、流程或系统如何工作？ | 对象与范围 -> 输入/条件 -> 处理过程 -> 输出 -> 例外与边界 |

### 1.3 用第一页聚焦，用最后一页推动行动

- 第一张实质内容页优先回答"为什么现在讨论、需要关注什么、整份材料将回答哪些关键问题"。可使用执行总结、关键趋势或问题总览，不必依赖口头开场。
- 总览页提出的关键问题、趋势或判断，后续必须逐项展开；不要提出后文不回答的问题。
- 最后一张实质内容页说明"建议做什么、预期达到什么、何时完成、由谁负责、需要什么资源、存在哪些风险、需要领导决定什么"。
- 对领导汇报或需要归档转发的材料，优先保留一页执行总结。根据实际内容包含目的、主要问题或趋势、原因或差距、方案、目标和计划；不存在的要素不强行补齐。

## 2. 通用论证结构

围绕以下四层组织材料：

1. **事实**：公开资料、产品能力、数据、截图、接口、规则或已确认现状；
2. **机制或对比**：事实之间如何关联，与原流程或竞品有什么差异；
3. **边界判断**：已经覆盖什么，间接支持什么，尚未覆盖或未公开什么；
4. **业务影响**：对平台、商家、客户、运营或下一步决策意味着什么。

不要求每页同时包含四层，但整份报告必须形成完整链条。没有证据时不直接给出战略结论。

对于需要推动决策的材料，补充六个要素：

1. **目的**：为什么讨论，最终希望实现什么；
2. **问题**：当前状态与应有状态之间的关键差距，不把一般现象直接当问题；
3. **原因**：造成差距的根因，不停留在表层症状；
4. **解决方案**：先提出候选方案，再按效果与可行性选择；
5. **目标**：给出期限、目标值、口径和基线；
6. **计划**：说明时间、关键步骤、责任、资源、预算、风险与验收。

六要素是检查框架，不是固定六页模板。可以合并，但不得让方案与问题脱节。将"识别问题"与"选择方案"分开；不要从症状直接跳到行动。

## 3. 不同任务的叙事结构

### 3.1 能力拆解或竞品功能洞察

1. 总体结论与能力范围；
2. 入口、对象与适用条件；
3. 关键流程或机制；
4. 新旧流程或竞品差异；
5. 已覆盖与未覆盖边界；
6. 真实价值与可借鉴点。

短报告可合并相邻环节，但不能省略能力边界。

### 3.2 竞品比较

1. 比较范围和统一维度；
2. 原生对比表呈现事实；
3. 解释两到三个关键差异及形成原因；
4. 说明对当前产品的影响；
5. 给出优先补齐项或继续验证项。

不要先给每家厂商单独做一页功能罗列，再在最后重复比较。优先按同一维度并排比较。

### 3.3 趋势洞察：一种可选的外到内结构

当任务需要判断外部趋势并进一步评估自身影响时，可以采用以下结构：

1. 总览页提出需要回答的关键趋势或问题；
2. 行业：用数据、政策、技术变化或客户行为说明外部变化；
3. 友商：用多个独立厂商动作验证趋势并说明不同路径；
4. 机制：解释共同方向、差异及其形成原因；
5. 自我：对照相同维度评估当前能力、资产、入口和差距；
6. 影响：说明对客户、商家、平台和业务结果的含义；
7. 建议：逐项对应前述趋势、问题或差距，并明确验证事项与计划。

至少使用两个相互独立的证据支撑趋势，避免由单一案例推导行业结论。

趋势较多时，先在总览页提出三至五项关键趋势，再逐项展开。不要先罗列行业、友商和自身的全部信息，最后才临时总结；每个趋势展开页都要说明其证据、影响和与下一部分的关系。若研究问题不是外部趋势，不使用这条结构。

### 3.4 方案评审

1. 问题、目标和约束；
2. 候选方案及共同评价维度；
3. 原生决策表比较成本、收益、风险和依赖；
4. 推荐方案及理由；
5. 实施步骤、风险与待决策事项。

问题页先定义应有状态，再用定量数据说明整体规模、用定性案例或截图说明单点严重性。采用二八原则筛选关键问题。原因页通过多轮"为什么"或根因树区分直接原因、机制原因和基础能力缺口。方案页先广泛提出候选项，再使用原生决策表按效果、可行性、成本、周期、风险和依赖进行选择。

### 3.5 运营复盘

1. 目标、周期和口径；
2. 核心指标及趋势；
3. 异常点和影响；
4. 原因及证据；
5. 改进动作、责任人、时间和验收标准。

### 3.6 能力现状与建设规划

1. 业务目标、用户任务和适用范围；
2. 当前能力总览与事实依据；
3. 对标对象和统一比较维度；
4. 关键缺口及其业务影响；
5. 建设原则、候选路径和优先级；
6. 分阶段目标、里程碑、责任、依赖和验收指标。

## 4. 信息筛选与量化

### 4.1 先完整整理，再筛选主线

1. 先列出所有可能影响判断的信息，不在搜集阶段过早删减；
2. 标出汇报时限内必须传达的结论和证据；
3. 按读者容易理解的顺序排列；
4. 将次要方法、长清单和原始明细放入附录，但核心证据留在正文；
5. 检查每项建议是否能回溯到正文中的问题、根因、差距或机会。

研究与人工补充不是二选一。公开资料可先证明行业、竞品或产品机制，内部截图、数据、专家判断和最终结论再补充本方现状、效果或立场。

### 4.2 同时使用三种视角

- **产品立场**：从效果、可行性和业务价值出发给出明确判断，不只做中性资料搬运；
- **决策者视角**：根据参会角色补足其关心的收益、成本、风险、依赖、责任和可控性；
- **数字视角**：优先使用真实数据。没有直接数据时，可用`总量 × 比例`或`单次影响 × 发生次数`进行可解释测算，并标明假设、口径和区间，不将估算写成事实。

### 4.3 用现状与目标定义问题

问题必须体现`As-is（当前状态）`与`To-be（应有状态）`之间的差距。使用定量证据说明规模、频次、趋势或影响，使用定性证据说明具体表现和严重性。区分：

- 现象：已观察到的结果；
- 问题：影响目标达成的关键差距；
- 原因：产生差距的机制；
- 约束：短期无法消除、方案必须适应的条件。

## 5. 单页组织

每页按以下顺序检查：

1. **标题**：说明该页的目标、问题、原因、方案、目标值或计划；
2. **主要信息**：用一至两句写出本页最希望读者确认的结论；标题已经完整表达时可以省略，不能与标题重复；
3. **导语或口径**：仅在范围、时间、定义或读法需要解释时使用；
4. **主体证据**：表格、图表、截图、流程、案例或少量模块，直接证明主要信息；
5. **边界或解释**：说明未覆盖项、限定条件、关键机制或反例；
6. **来源**：页内短来源，备注内完整链接。

标题与正文必须构成直接关系：正文删除后标题失去依据；标题删除后正文仍能看出它证明什么。

复杂页面可以增加一个短结论区，但不要重复标题。结论区用于回答"这些证据共同说明什么"。

"一页一个观点"指一页只有一个主要判断或叙事任务，不意味着只能放一项事实。只要数据、案例、流程和限定条件共同证明同一观点，就应保留在同页。若一页同时承担"解释问题"和"选择方案"两个独立任务，应拆分页面。

常见正文证据：

- 目的页：发生了什么、为什么现在讨论、达成后会改善什么；
- 问题页：现状、应有状态、差距规模和代表性案例；
- 原因页：根因结构、流程瓶颈、调查结果或一线反馈；
- 方案页：候选方案、优缺点、效果与可行性比较、推荐项；
- 目标页：基线、目标值、期限和测量口径；
- 计划页：时间表、责任分工、资源预算、依赖、风险和验收标准。

## 6. 精简、密度与阅读顺序

- 首要目标是保留决策相关信息。只删除不影响理解和判断的背景铺垫、重复定义、同义结论和无效修饰语。
- 将重复句式转为表格行或流程节点。
- 将长段落拆成"对象—动作—结果—边界"，但保留必要的主语、范围、数字口径和限定词。
- 一页优先保留三类信息：支持结论的事实、影响判断的边界、领导需要知道的业务含义。
- 需要截图预留位时，提前为截图分配版面，不先将文字铺满后再压缩。
- 页面不足以容纳全部内容时，按顺序处理：删除重复表达 -> 改用更高效的原生表格、图表或流程 -> 拆成两张连续页面 -> 将次要明细移入附录。不要把核心证据移走，也不要通过过小字号解决。
- 使用逐条列举、数字序号、统一的语法结构和信息层级。首次出现的简称或专有名词补充括号说明。
- 通过现状与目标、我们与友商、方案A与方案B、投入与效果的对比降低理解成本；适当加入成功案例，帮助读者判断可行性。
- 按页面形态建立明确的目光顺序：横向多列内容使用自然的左到右、上到下顺序；纵向流程保持自上而下或倒N形承接。编号、箭头和讲解顺序必须一致，避免视觉顺序与论证顺序冲突。
- 保持页面结构稳定，默认使用标题、主要信息、正文和来源。线条、颜色和装饰只服务于分组、比较和强调；删除无意义边框、箭头和背景图形。
- 同一层级保持一致的对齐、间距和句式。
- 留白用于分隔信息层级，不追求大面积空白，也不为了填满页面添加装饰。

## 7. 三轮检查

分三轮完成，不合并成一次快速浏览。

### 7.1 结构与对应关系

- 主线能否用一句话说明？
- 第一页提出的问题、趋势或判断是否在后文逐项回答？
- 前半部分的问题、根因、差距是否与后半部分的方案、目标和计划逐项对应？
- 是否区分现象、问题、原因与约束？
- 是否存在无关页面、重复页面或论证跳跃？
- 执行总结是否准确覆盖正文，而不是增加正文没有证明的结论？

### 7.2 表达、阅读与讲解

- 每页是否只有一个主要观点，但保留了证明它所需的充分细节？
- 标题、主要信息和正文是否形成明确的结论—证据关系？
- 载体是否匹配信息关系，行列信息是否使用原生表格？
- 目光顺序、编号、动画和讲解顺序是否一致？
- 页面不看备注时能否理解，出声朗读时是否在预定时间内讲清？
- 是否存在字号过小、内容拥挤或为了美观删掉关键证据？

### 7.3 事实与细节

- 整份报告是否形成"事实—机制或对比—边界—影响"的完整链条？
- 标题是否被本页证据直接支持？
- 是否把推断写成了事实？
- Agent 可自主获得的证据是否已经研究并注明来源，而不是被人工待补项替代？
- 人工待补截图、数据或结论是否有稳定ID、责任、格式、用途、阻断级别和到位后更新规则？
- 公开证据与人工材料共同支持同一判断时，二者的分工和当前可成立结论是否清楚？
- 数字是否核对单位、时间、范围、基线、目标值和口径？
- 部门、人名、产品名、专有名词、来源、链接和日期是否正确？
- 是否存在错别字、丢字、重复字、残留占位符或错误截图标注？
- 领导读完后是否清楚需要知道、判断或决定什么？
