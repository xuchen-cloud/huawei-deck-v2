# 产品汇报页型选择

本索引面向产品洞察、能力拆解、竞品分析、运营复盘和方案评审。先根据内容关系选择页型，再决定具体视觉。不要为了复用官方样式而改变论证结构。

载体选择的信息关系映射见 `visual-system.md §5`；本文件聚焦"页型"——一种内容任务与版式轮廓的对应关系，粒度比信息关系更粗，直接服务于"这页该长什么样"。

## 1. 默认页型

| 页型 | 适用内容 | 首选实现 |
|---|---|---|
| 简洁封面 | 标题、范围、副标题、作者或团队、日期 | 原生文字与少量线条 |
| 核心结论 | 2至4条确认结论、关键边界、必要的决策事项 | 分栏或简洁结论区 |
| 能力范围 | 入口、对象、输入、输出、适用条件 | 原生表格或分层图 |
| 流程机制 | 操作步骤、角色流转、AI与人工分工 | 原生流程图或泳道 |
| 前后对比 | 旧流程与新流程、AS-IS与TO-BE | 原生对比表或双栏流程 |
| 竞品对比 | 多个对象按统一维度比较 | PowerPoint原生表格 |
| 能力边界 | 已覆盖、间接支持、未覆盖、未公开 | PowerPoint原生表格 |
| 架构分层 | 平台、能力、运行时、治理及外部系统关系 | 原生形状与连接线 |
| 截图实证 | 产品入口、界面、生成结果、配置项 | 截图加少量标注和解释 |
| 数据趋势 | 指标变化、数量比较、占比和分布 | 原生图表 |
| 原因分析 | 现象、直接原因、深层原因和证据 | 根因链或因果图 |
| 方案决策 | 方案、收益、成本、风险、依赖和推荐 | PowerPoint原生表格 |
| 路线图 | 阶段、交付物、时间、负责人和状态 | 甘特或原生里程碑表 |
| 风险对策 | 风险、影响、对策、责任人和时间 | PowerPoint原生表格 |
| 下一步与决策 | 行动、Owner、时间、验收标准、待决策项 | PowerPoint原生表格或分栏 |

## 2. 任务与页型映射

### 2.1 能力拆解或竞品洞察

优先顺序：核心结论 -> 能力范围 -> 流程机制 -> 前后或竞品对比 -> 能力边界 -> 真实价值。

### 2.2 趋势洞察

优先顺序：趋势判断 -> 事实或厂商动作表 -> 机制或共同方向 -> 影响 -> 建议和验证项。

### 2.3 方案评审

优先顺序：问题与约束 -> 方案决策表 -> 推荐方案 -> 实施路径 -> 风险与待决策项。

### 2.4 运营复盘

优先顺序：指标摘要 -> 趋势图 -> 异常与原因 -> 改进动作 -> 责任人与时间。

## 3. 按需页型

以下页型不是默认项，只在内容或场合确实需要时使用：

| 页型 | 启用条件 |
|---|---|
| 目录或章节页 | 页数较多且需要章节导航 |
| 大数字页 | 数字本身是主要证据，且有完整口径和来源 |
| 深色总结页 | 需要明确章节转折或总结，且不会造成风格跳脱 |
| 官方摄影KV封面 | 用户要求忠实华为模板或提供主视觉 |
| Logo页脚 | 用户提供模板或明确品牌规范 |
| 密级或Security Level | 用户提供明确密级 |
| 二维码页 | 有真实入口且汇报目标包含引导访问 |
| Thank you或使命宣言页 | 正式演讲礼仪或忠实复刻要求 |
| 荣誉墙、双轮驱动、穹顶使命、金句页 | 内容关系确实对应，且用户要求宣传型表达 |

## 4. 禁止机械套用

- 不连续使用卡片墙承载本可用表格或图表表达的内容。
- 不将竞品比较、状态矩阵、风险清单或计划表拆成若干文本框。
- 不为了"结论先行"在每页加一条重复标题的底部结论条。
- 不为了华为风格自动添加雪山红伞、红角框、使命宣言、Huawei Confidential或全局Logo。
- 不把关键事实全部移到附录，使正文只剩口号。
- 不用大字和留白掩盖证据不足；资料型汇报优先保证可独立阅读。
- 不默认使用伪3D、发光圆环、穹顶、红角框、装饰箭头和大面积红块。
- 不为了"高级感"连续使用深色页或金句页。

## 5. 受控升级

当默认页型无法清晰表达某页的主要证明对象时，允许在固定页型基础上做有限升级。升级不是从空白开始自由设计，而是"页型 + 局部变体"。

### 允许的升级

在双轴逐字稿视觉轴中标记为 `页型名 + 局部变体`（如"方案决策 + 侧栏 takeaway"），不写"自定义"：

- 组合两个默认页型的轻量组件，保持一个基础页型；
- 为关键页增加证明对象旁的标注栈、侧栏或结论条；
- 将重复页型序列中的一页换成视觉轮廓明显不同的页型（如连续表格中插入一个流程或大数字页），打破节奏单调；
- 为复杂方法图、实验结果或业务指标页创建局部布局。

### 必须满足的条件

- 仍从默认页型出发，不从空白开始；
- 仍填写双轴逐字稿并走确认门；
- 仍执行五轮 QA（含 E 轮 Deck 整体检查）；
- 仍使用原生可编辑对象、华为视觉系统和 `visual-system.md` 的 token；
- 不为"高级感"牺牲可读性、可编辑性或可复现性。

### 回退规则

升级页在视觉 QA 中失败两次，或在 Deck 整体检查（E 轮）中失败一次时，保留内容并回退到最近的默认页型。不通过反复修改升级版来解决——回退到基础页型比修补一个不稳定的升级更可靠。
