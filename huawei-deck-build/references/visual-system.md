# 华为视觉系统

本文件只包含华为风特有的视觉规则和 PowerPoint 可读性硬指标。通用叙事与写作理论不在此维护。

## 1. 颜色

| 色值 | 角色 | 用法 |
|---|---|---|
| `#C7000B` | 华为红 | 本页重点、选中项、关键路径、关键数字、风险 |
| `#A5000A` | 深红 | 深色强调或红色文字的高对比变体 |
| `#1A1A1C` | 主文字 | 标题、正文重点 |
| `#585860` | 次文字 | 说明、注释、次要信息 |
| `#E7E7E7` | 边框 | 表格线、分隔线、卡片边框 |
| `#F3F4F6` | 浅灰底 | 表头、分区、弱强调 |
| `#FAFAFA` / `#FFFFFF` | 页面底色 | 默认浅色页面 |
| `#1A1A1C` | 深色页面 | 少量章节转折或总结页；与主文字同色，保持体系统一 |
| `#E8A33D` | 深色页金色 | 深色页主要强调色 |

- 同一页除截图和数据系列外，只使用红、灰和中性色。
- 红色只承担少量重点：关键数字、选中路径、关键结论、风险。标题默认深灰或黑色，不用整行红色标题，不用红色铺大面积背景。
- 图表重点系列用红色，其余用灰阶或低饱和辅助色。真实截图保留原生配色。
- 深色页仅用于章节转折或关键总结：近黑背景、白字、金色强调、红色仅作品牌锚点；不连续使用深色页。

## 2. 字体与文字设计 Token

- 中文统一 `Noto Sans CJK SC`；需要衬线效果时用 `Noto Serif CJK SC`。不混用 `Noto Sans SC`、微软雅黑、苹方或未验证别名。字体预检与渲染策略见 `pptx-build-and-qa.md`。
- 字重只用 Regular / Bold 两档（随附字体包即这两档）。

### 2.1 文字颜色角色

| 角色 | 色值 | 用途 |
|---|---|---|
| 主文字 | `#1A1A1C` | 标题、正文、表格主体 |
| 次文字 | `#585860` | 导语、补充说明、图表标注 |
| 弱化文字 | `#76767C` | 来源注释、页码；对比度不低于 4.5:1，9pt 小字仍可读 |
| 强调红 | `#C7000B` | 关键数字、选中项、关键结论；每页不超过 2 处 |
| 深色页 | 主 `#FFFFFF` / 次 `#D9D9DC` / 弱化 `#8A8A90` / 强调 `#E8A33D` | 仅章节转折或关键总结页；来源注释与页码用弱化灰（深底对比度 ≥4.5:1） |

### 2.2 字号 Token 表

| 文字类型 | 使用场景 | 推荐值 | 下限 | 颜色 | 字重 |
|---|---|---|---|---|---|
| 封面标题 | 封面主标题 | 40pt | 32pt | 主文字 | Bold |
| 封面副标题 | 范围、作者、日期 | 16pt | 14pt | 次文字 | Regular |
| 页面标题 | 内容页左上结论式标题 | 28pt | 24pt | 主文字 | Bold |
| 页面导语 | 标题下的范围/口径说明 | 14pt | 12pt | 次文字 | Regular |
| 模块标题 | 卡片、分区、表组标题 | 18pt | 16pt | 主文字 | Bold |
| 正文 | 段落、要点列表 | 12pt | 10pt | 主文字 | Regular |
| 强调正文 | 结论条、重点句 | 12pt | 10.5pt | 主文字或强调红 | Bold |
| 补充说明 | 边界、机制解释、辅助注释 | 10.5pt | 9.5pt | 次文字 | Regular |
| 表格表头 | 原生表格首行 | 11pt | 10pt | 主文字（浅灰底） | Bold |
| 表格内容 | 表格数据单元格 | 10.5pt | 9.5pt | 主文字；次要列可用次文字 | Regular |
| 图表标注 | 坐标轴、数据标签、图例 | 10pt | 9pt | 次文字；重点系列用主文字 | Regular |
| 大数字 | 关键指标数值 | 40pt | 32pt | 强调红或主文字 | Bold |
| 大数字单位 | 数值旁单位与口径 | 12pt | 10pt | 次文字 | Regular |
| 标签徽章 | 状态标签、chip、图例块 | 10pt | 9pt | 主文字或状态色 | Regular |
| 来源注释 | 页内短来源、脚注 | 9pt | 8pt | 弱化文字 | Regular |
| 页码 | 页脚 | 9pt | 8pt | 弱化文字 | Regular |

### 2.3 一致性硬规则

- 同一文字类型在所有页面使用同一 token（字号、颜色、字重完全一致）；同一页内同类文字只允许一个 token。
- 内容放不下时走 `pptx-build-and-qa.md` 容量预检的处理阶梯（压缩表达 → 改载体 → 调整比例 → 附录 → 拆页），不得通过偏离 token 解决。
- 使用官方模板时以模板字号为推荐值，但不得低于上表下限。
- 确需偏离 token 的特例，在 `page-script.md` 该页视觉轴中显式记录类型、取值和原因，并在 `qa-report.md` 记录实际实现。
- 标题按单行设计时不得换行；确需两行时按语义显式断行，不用缩字号解决。

## 3. 受保护文本

以下文本在构建和换行中受保护，不得在单词或语义中间机械断开：

- 公司名、产品名、品牌名（如 Huawei、KooGallery、AgentCore）；
- API 名、字段名、命令行、代码标识符；
- 数字与单位的组合（如 35pt、¥1,200、99.9%）；
- URL、邮箱、版本号。

实现上优先整体换行或调整容器宽度；构建后 QA 逐页检查是否存在品牌名拆分、单词中间换行和孤行。

## 4. 页面骨架

默认 16:9。内容页使用稳定骨架：

1. 左上标题：一句具体、可验证的事实或判断；证据只支持中性描述时不强行拔高为战略结论；
2. 可选导语：限定范围、口径或读法，需要时才用；
3. 主体：承担主要证据；
4. 页脚：页码和简短来源，需要时加口径说明。

- 阅读顺序默认左到右、上到下；纵向流程自上而下。编号、箭头、视觉顺序和论证顺序保持一致。
- 卡片只用于彼此独立、同级、可单独移动的内容模块；不把全部信息装进圆角卡片，不连续三页使用相同卡片墙布局。
- 删除无信息量的边框、箭头、背景图形、伪 3D、发光、重阴影和过度圆角。

## 5. 载体选择

| 信息关系 | 首选载体 | 使用条件 |
|---|---|---|
| 精确映射、逐项比较、状态盘点 | 原生表格 | 存在明确行列语义 |
| 趋势、数量差异、占比、分布 | 原生图表 | 数字关系比单个值更重要 |
| 步骤、阶段、事件顺序 | 流程或时间线 | 顺序和转换关系构成含义 |
| 层级、归属、系统边界 | 架构图或分层图 | 空间和连接关系构成含义 |
| 产品界面、公开功能证据 | 截图加标注 | 需要证明入口、交互或配置 |
| 2 至 4 个独立同级事实 | 简洁分栏或卡片 | 各项没有稳定行列关系 |
| 单个关键结论或数字 | 直接文字或大数字 | 不需要额外结构；数字须附口径和来源 |

- 行列语义明确时一律使用原生 PowerPoint 表格，不用矩形加文本框拼接，也不拆成卡片。
- 图表选择：构成占比用饼图/100% 堆积（类别少且总和有意义时）；对象比较用柱状/条形；时间变化用折线；优先级评估用矩阵或决策表。
- 图解只保留表达关系所需的节点与连线。

## 6. 表格与图表规则

- 原生表格适用于具有明确行列语义的内容：竞品对比、能力矩阵、状态或覆盖矩阵、方案对比、API 或字段映射、计划、风险、职责与精确数字表格。
- 浅灰表头、细边框、适度内边距、文本左对齐、数字右对齐；突出整行、整列或少数关键单元格，不给每列染不同颜色。
- 合并单元格只用于真实分组。
- 表格安全规则：为页脚和来源保留固定安全区；构建前按最长单元格预估列宽与行高；单元格内容过长时先压缩表达或调整列权重，超过容量按已确认的超载规则处理，不缩小到下限字号以下。
- 若生成库无法创建所需的原生表格样式，选择更简单的原生表格设计，或在交付说明中声明限制；不要静默回退到形状拼出的表格。
- 图表标题不与页面标题重复；只保留帮助判断的轴、标签、图例和基准线；每个关键数据标明时间范围、单位、口径和来源。
- 截图保留完整界面语境，裁掉无关浏览器边框和空白；关键区域用少量编号或线框标注并在旁边解释"看到什么、说明什么"；不拉伸变形，不为填满容器过度裁切。

## 7. 页面元素的默认与例外

| 元素 | 默认处理 | 仅在以下情况启用 |
|---|---|---|
| 封面 | 简洁标题、范围或副标题、作者或团队、日期 | 用户要求官方模板或主视觉封面 |
| Logo | 不装饰性放置 | 用户提供模板或明确品牌要求 |
| 密级 / Security Level | 不添加 | 用户提供明确密级 |
| 使命宣言 / Thank you 页 / 二维码页 | 不添加；以"结论与下一步"收尾 | 用户明确要求或正式演讲礼仪确有需要 |
| 目录或章节页 | 短报告不使用 | 页数较多且章节导航确有价值 |
| 底部结论条 | 按需使用 | 复杂证据需要一句收束，且不重复标题 |
| 大数字页 | 按需使用 | 数字本身是主要证据且口径完整 |

## 8. 密度与阅读顺序

- 信息传递优先于视觉极简。默认面向"无需讲解也能读懂"：页面正文包含结论所需的关键事实、机制、边界、数据和来源。
- "一页一个观点"指一个主要判断或叙事任务，不限制支撑事实的数量；共同证明同一结论的数据、流程、案例和限定条件保留在同页。
- 高密度通过结构实现：表格替代重复卡片、图表替代数字列表、流程替代步骤段落、截图标注替代长篇描述；不靠缩小字号。
- 面向无需讲解阅读的材料，偏好密集、结构良好的证据页。使用层级、对齐、简洁短语和正确的信息载体，而不是用装饰性卡片填充空间。
- 在舒适可读的前提下，尽可能保留与决策相关的细节；使用分节、表格、图表、对齐和跨页渐进式披露来管理密度。
- 只把次要明细、完整方法、长列表和原始备份放入附录；核心证据留在正文，不藏在备注或附录。
- 同一事实只在最需要的位置完整出现，其他页面用短引用承接。
- 语义模块（卡片及内容、时间线事件、流程步骤、标注节点等）组成原生 PowerPoint Group Shape，保持可组合、可取消组合；原生表格、图表和需要独立编辑的连接线不强制组合。细则见 `pptx-build-and-qa.md`。
- 同一层级保持一致的对齐、间距和句式。
- 留白用于分隔信息层级，不追求大面积空白，也不为了填满页面添加装饰。

## 9. 写作风格

本节定义标题与正文的最终视觉检查。通用语言原则和推断标注已由确认后的 `page-script.md` 固化；构建阶段只检查其实现是否符合下列写法和视觉反模式，不重新改写观点。

### 9.1 标题

- 标题直接写清谁做了什么、覆盖什么、产生什么变化，或该页确认了什么事实。
- 允许中性事实标题，不要求每页都形成宏大战略判断。
- 避免只有栏目含义的标题，如"市场分析""能力介绍""价值分析"。如果证据不足以形成结论，写清分析对象和范围。
- 标题原则上保持单行；确需两行时按语义断句，不缩成难以阅读的小字号。

示例：

| 场景 | 推荐 | 避免 |
|---|---|---|
| 能力范围 | AI辅助上架同时覆盖新商品创建和存量商品优化 | 从内容生成走向全生命周期治理 |
| 技术边界 | GEO提高商品被检索和理解的可能性，但不提供Agent调用接口 | Agent发现能力全面升级 |
| 对比判断 | AWS覆盖生成、校验和评分，定价与交付配置仍由卖家完成 | AWS重塑商品上架全流程 |

### 9.2 正文

- 使用短句和短语提高扫描效率，但不要为了"胶片感"删除必要的主语、范围或限定词。
- 卡片标题写成明确对象或判断，不强制四字口号。
- 每个模块先写对象，再写能力或变化；避免同一层级混用名词、动词和口号。
- 关键词强调每页控制在少数几处。优先用字重、红色或位置层级中的一种，不叠加多种装饰。
- 数字必须附单位、时间范围和口径；外部数据在页内保留简短来源。

### 9.3 视觉反模式

以下华为官方样式中常见的装饰手法默认不使用，除非用户明确要求忠实复刻：

- 伪 3D、发光圆环、穹顶、红角框、装饰箭头和大面积红块；
- 连续使用深色页或金句页制造"高级感"；
- 把全部信息装进圆角卡片或连续三页卡片墙；
- 为每页加重复标题的底部结论条；
- 自动添加雪山红伞、使命宣言、Huawei Confidential 或全局 Logo。

### 9.4 最终检查清单

构建完成后逐页检查：

- 标题是否具体、可验证，并被正文直接支持？
- 是否删除了套路化升华、宣传口号和无依据判断？
- 核心事实、机制、边界和来源是否在页面上？
- 页面在不看备注时是否能够理解？
- 是否为了视觉精简删除了影响判断的事实、机制、边界、数据或案例？
- 内容过多时是否先改用高效载体或拆页，而不是缩小字号？
- 行列信息是否使用原生表格，而不是文本框拼接？
- 红色是否只用于少量重点？
- 是否错误添加了 Logo、密级、使命宣言、二维码或礼仪页？
- 修改已有内容时，是否保留了用户原有编号、术语和清楚表达？
- 是否用直接的事实性措辞替换了无依据的拔高、模糊名词、不必要的修辞框架和口语化的舞台指示？
