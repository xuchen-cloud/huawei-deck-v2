# 双轴逐字稿示例

本文件只展示信息轴和视觉轴应具体到什么程度，不新增结构、内容或视觉规则。以下业务内容均为示意，不作为真实产品事实。

## 正例一：高密度左右分栏流程对比

```markdown
## P06 AI 辅助上架在内容准备阶段增加统一输入、字段级校验和修改留痕

### Narrative role
- task：解释 AI 接入前后，商品内容准备流程、系统职责和人工责任发生了什么变化。
- previous-page response：承接上一页提出的“内容字段重复录入、质量问题集中在提交前暴露”。
- next-page setup：为下一页拆解生成服务、规则服务与编辑器的接口关系提供流程基础。

### Information axis
- core claim：AI 覆盖商品内容的准备与校验；定价、交付配置、事实真实性和最终发布仍由卖家确认。
- information relationship：AS-IS / TO-BE 同阶段对比；两栏均按“输入 → 生成或撰写 → 校验 → 确认发布”展开。

- complete on-slide copy：
  - 导语：对比范围为商品基本信息进入系统后，标题、卖点、长描述和属性说明从准备到发布前确认的全过程；不包含定价策略和履约执行。

  - 左栏标题：AS-IS｜人工串行准备，问题在末端集中暴露
  - 左栏 01｜整理输入
    - 商品名称、类目、规格、图片与资质信息分散在多个材料中。
    - 卖家筛选可用字段，再逐项录入上架页面。
  - 左栏 02｜分字段撰写
    - 标题、核心卖点、长描述和属性说明分别编写。
    - 同一商品事实被多次转述，字段间容易出现术语、数值和口径不一致。
  - 左栏 03｜末端检查
    - 按清单核对必填、长度、敏感词、类目属性和跨字段一致性。
    - 问题在内容完成后集中暴露，修改需要返回不同编辑区。
  - 左栏 04｜返工与提交
    - 任一字段不合格都会触发对应内容返工，修改记录缺少统一关联。
    - 卖家补充定价与交付配置，完成最终确认后提交发布。

  - 右栏标题：TO-BE｜统一输入驱动生成与字段级校验
  - 右栏 01｜结构化输入与预检
    - 系统汇总类目、规格、图片识别结果和资质字段，形成统一商品事实。
    - 生成前检查关键输入；缺失项返回来源补齐。
  - 右栏 02｜多字段生成候选稿
    - 模型基于同一商品事实生成标题、卖点和长描述候选稿。
    - 系统保留输入字段、提示词版本、模型版本与生成结果之间的追踪关系。
  - 右栏 03｜字段级校验与定点修改
    - 返回必填、长度、敏感词、属性冲突和术语一致性结果。
    - 结果包含字段路径、严重级别、原因、建议和规则版本。
  - 右栏 04｜人工确认与发布
    - 记录建议采用情况、最终内容和规则版本，支持问题回溯。
    - 定价、交付配置、事实真实性和最终发布仍由卖家确认。

  - 底部信息组｜职责与实现落点
    - 系统职责：统一商品事实，生成候选内容，返回可定位、可解释的字段级校验结果。
    - 人工职责：确认商品事实和主观表达，处理价格与履约配置，承担最终发布责任。
    - 实现要求：输入输出使用稳定字段 schema；生成和规则结果保留版本、来源、采用状态与操作者。

  - 页内短来源：示例页；正式版本替换为产品流程文档、字段协议、规则清单和编辑器实证。

- evidence IDs and source locators：
  - EX-P06-01｜现行上架流程与编辑器字段｜示例占位。
  - EX-P06-02｜生成服务输入输出协议｜示例占位。
  - EX-P06-03｜规则服务返回结构与版本机制｜示例占位。
  - EX-P06-04｜发布责任与审计要求｜示例占位。

- inference or recommendation：
  - 建议将“统一商品事实”和“字段级问题对象”作为生成服务、规则服务与编辑器之间的公共协议；该建议需在接口方案评审中确认。

- concise speaker notes：
  - 左侧问题不只是人工耗时，还包括同一商品事实被多次转述，以及错误集中到末端发现。右侧将输入预检、同源生成和字段级校验串联起来，并通过字段路径、规则版本和采用记录保证结果可定位、可解释、可追踪。自动化覆盖内容准备，但价格、履约、真实性与发布责任没有转移。
  - 转场：下一页具体说明三类服务之间传递哪些字段，以及异常时如何降级。

### Visual axis
- primary proof object：AS-IS / TO-BE 四阶段双栏流程对比。
- page type and carrier：前后对比 + 底部职责与实现落点；使用原生文本、形状和连接线。
- layout regions and reading order：
  - 顶部为结论式标题和一行范围说明。
  - 主体左右等宽：AS-IS 和 TO-BE 各使用一个完整的父级大框，大框内包含栏标题和四个流程阶段；两栏同阶段水平对齐，先读左栏，再读右栏。
  - 两个父级大框之间保留清晰的迁移通道，用一枚横向宽带箭头表达从现状到目标态；箭身和箭头轮廓在整页缩略图下仍能立即识别，箭头不侵入任一栏的内容区域。
  - 底部横向分为“系统职责、人工职责、实现要求”三个信息组。
  - 来源位于页脚，不进入主体阅读路径。
- focus and emphasis：
  - 两个父级大框先建立“现状域”和“目标态域”的整体归属：AS-IS 使用中性浅灰处理，TO-BE 使用克制的浅红强调；两栏外框尺寸、标题位置和内部节奏保持对应。
  - 迁移箭头是两栏之间的主关系符号：使用华为红原生块状箭头，不使用细线末端的小三角；箭头高度与栏标题区形成同一视觉量级，左右留出安全间距，并保持在两栏之间的迁移通道内。
  - 栏标题作为父级大框的顶部标题区，不再悬浮为框外的独立条带。
  - 父级大框承担主要边界，四个阶段使用弱分隔或低对比子容器组织，形成连续流程，避免出现“大卡片内嵌四张同等重量小卡片”的碎片感。
  - 主要视觉差异放在右栏“字段级校验与定点修改”的返回路径。
  - 左右两栏保持相同容器结构，依靠内容和连接关系表达差异。
  - 底部职责与实现落点是两种状态对比后的共同结论，位于两个父级大框之外；“实现要求”作为研发读者的次级焦点，不与主流程竞争。
- native editability and semantic groups：
  - 每个流程阶段由子容器或分隔区域、编号、阶段名和两条说明组成一个子语义组；选择或移动该阶段时，区域与文字保持整体。
  - AS-IS 的父级大框、栏标题、四个阶段子组和栏内顺序连接线组成一个整栏父级语义组；TO-BE 采用相同的嵌套分组结构，返回线归入 TO-BE 父级组。
  - 两栏之间的迁移箭头保持独立可编辑；移动任一整栏时，其大框、标题、阶段内容和栏内关系同步移动。
  - 底部每个信息组由容器背景、组标题和正文组成一个语义组；连接线保持可单独编辑。
- capacity budget and overflow response：
  - 当前承载两栏各四个阶段，每阶段一个短标题和两条说明，底部三个信息组。
  - 若真实字段或规则说明超过当前容量，主页面保留流程、输入输出和责任边界；字段协议与规则返回样例转入下一张接口明细页。
  - 若流程阶段增加，优先拆成“流程变化”和“接口及责任”两页，不压缩为难以阅读的小字。

### Blocking decisions
- EX-P06-01 至 EX-P06-04 均为示例占位；用于真实项目时，标题、流程差异和实现建议必须由对应证据替换并确认。
```

## 正例二：高密度复杂分布图

```markdown
## P09 上架能力的自动化方式取决于结果可验证性、错误影响和责任归属

### Narrative role
- task：按自动化决策方式组织上架能力，并说明不同层级对应的产品交互和工程治理要求。
- previous-page response：承接上一页已经确认的能力清单，回答“哪些能力可以自动执行，哪些必须保留人工判断”。
- next-page setup：为下一页确定服务分层、接口协议和建设优先级提供分类依据。

### Information axis
- core claim：可由结构化规则验证且错误可在发布前撤销的能力可以自动执行；涉及真实性、合规、价格、履约或发布责任的能力需要人工确认。
- information relationship：三圈层能力分布；从中心到外围依次为“自动执行、系统建议与人工处置、责任人决策”。圈层表示决策方式，不表示流程先后或功能优先级。

- complete on-slide copy：
  - 导语：节点越靠近中心，系统可自主完成的程度越高；能力位置由可验证性、错误影响、责任归属和输入充分性共同决定。

  - 左侧判定依据：
    - 可验证性：结果能否由 schema、确定性规则、引用字段或明确计算口径验证。
    - 错误影响：错误能否在发布前低成本撤销，是否会直接产生交易、履约或合规后果。
    - 责任归属：判断是否涉及事实真实性、主体资质、价格、服务承诺、审批或正式发布责任。
    - 输入充分性：生成或判断所需事实是否完整、可信，并具有稳定来源。

  - 中心层｜L1 自动执行
    - 标题生成｜规则可验｜类目、品牌、型号、规格和关键词约束。
    - 卖点与长描述｜字段可追踪｜统一商品事实生成，片段保留字段引用。
    - 图片标签提取｜低置信度拦截｜候选标签不直接写入主数据。
    - 格式归一化｜确定性转换｜统一单位、枚举值和字段格式。

  - 中间层｜L2 系统建议、人工处置
    - 属性补全｜禁止无来源覆盖｜附来源、置信度和冲突提示。
    - 跨字段一致性｜人工确认事实｜定位品牌、型号、数量和单位冲突。
    - 敏感与合规表述｜命中不等于结论｜按类目、地区和规则版本提示。
    - 质量评分｜只定位改进项｜不将评分直接等同于转化效果。
    - 类目与关键词推荐｜多候选需选择｜低置信度时由卖家选择。

  - 外围层｜L3 责任人决策
    - 定价与促销｜业务审批｜价格目标和促销约束由业务确认。
    - 交付与服务配置｜履约确认｜库存、交期和 SLA 由责任人确认。
    - 资质与真实性｜主体负责｜系统不替代资格、授权和事实责任。
    - 最终发布｜操作留痕｜记录操作者、采用内容和审批结果。

  - 右侧工程要求：
    - L1：稳定输入 schema、提示词与模型版本；保留字段级引用；执行自动回归和失败回退。
    - L2：统一问题对象；至少返回字段路径、严重级别、依据、建议、置信度和规则版本。
    - L3：提供确认、驳回、审批与审计链路；系统不得以默认勾选代替责任人决策。

  - 页内短来源：示例页；正式版本替换为能力清单、类目 schema、规则平台设计和发布审批规范。

- evidence IDs and source locators：
  - EX-P09-01｜上架能力清单与当前覆盖状态｜示例占位。
  - EX-P09-02｜类目 schema 与确定性校验规则｜示例占位。
  - EX-P09-03｜规则平台问题对象与返回字段｜示例占位。
  - EX-P09-04｜发布审批、责任和审计规范｜示例占位。

- inference or recommendation：
  - 建议按 L1、L2、L3 分别设计自动执行、人工处置和审批审计接口，避免所有能力共用同一种“生成后确认”交互；该分类需由产品、架构、合规和履约责任人共同确认。

- concise speaker notes：
  - 这张图按决策方式分类，不按功能价值排序。中心能力具有结构化输入和可验证输出，可以自动进入后续校验；中圈能力能定位问题或提供候选，但真实性、合规语境和候选选择仍需人工处置；外圈直接影响交易、履约和责任，系统只提供信息与风险提示。三圈对应三套不同的接口、交互和治理要求。
  - 转场：下一页将 L1、L2、L3 映射到生成服务、规则服务、工作流和审计模块。

### Visual axis
- primary proof object：三圈层、十三项能力的自动化决策分布图。
- page type and carrier：能力范围 + 三圈层分布图局部变体；使用原生形状、文本和连接线。
- layout regions and reading order：
  - 顶部为结论式标题和读图说明。
  - 主体使用左窄、中宽、右中等的三栏结构：左侧为四项判定依据，中部为三圈层能力分布图，右侧为 L1/L2/L3 工程要求；中部证明对象获得最大的连续空间。
  - 三个同心圈在中栏内完整展开并保留环间留白：L1 四个节点在内圈形成紧凑的 2×2 核心组；L2 五个节点沿中圈左右与下方均匀展开；L3 四个节点分布在外圈的左上、右上、左下和右下区域。
  - 圈层标签放在对应环带的空白区域，不压在能力节点、圆环边界或其他圈层标签上；每个节点的视觉中心落在所属圈层内，不跨越相邻圈层边界。
  - 阅读顺序为“判定依据 → 中心层 → 中间层 → 外围层 → 对应工程要求”。
  - 来源位于页脚。
- focus and emphasis：
  - 中部圈层图是唯一主视觉；左侧判定依据和右侧工程要求使用更稳定、克制的纵向排布，作为“为什么这样分”和“分类后怎么做”的解释栏。
  - 圈层使用“位置 + 明度 + 层级标签”共同编码：L1 节点和内圈使用强调处理，L2 节点使用弱灰区分，L3 节点保持白底和灰色边界；即使不依赖颜色，仍能通过空间位置和 L1/L2/L3 标签识别层级。
  - 右侧工程要求卡片复用同一层级编码：L1 使用浅红强调底，L2 使用浅灰底，L3 使用白底；三张卡片的边框、圆角、内边距和标题结构保持一致，使说明栏与圈层图形成直接对应。
  - L1 的 2×2 节点组与内圈居中对齐；L2、L3 节点围绕同一圆心建立近似对称的视觉平衡，但按节点文字长度做局部避让，不追求机械等角分布。
  - 能力节点不使用装饰性图标、阴影或额外连线；圆环只表达层级归属，不承担装饰作用。
  - 每个节点完整显示信息轴规定的“能力名、边界标签和说明”；构建阶段不另行删改页面原文。
- native editability and semantic groups：
  - 每个能力节点由节点容器、能力名、边界标签和说明组成独立语义组；选择或移动节点时，容器与文字保持整体。
  - 三个圈层背景组成一个背景组；每层标题保持独立可编辑。
  - 每项判定依据由标题、说明和分隔线组成一个语义组；每段工程要求由容器背景、层级标题和正文组成一个语义组；关联线保持可单独编辑。
- capacity budget and overflow response：
  - 当前承载三个圈层、十三个能力节点、左侧四项判定依据和右侧三段工程要求。
  - 每个能力节点的可见文字固定为“能力名 + 边界标签 + 一句说明”；更长的机制、输入输出或例外进入已确认的分层明细页，不在构建阶段临时删减。
  - L1 默认承载 4 个节点并采用 2×2 排布；L2 默认承载 5 个节点；L3 默认承载 4 个节点。某层节点增加时，先检查是否仍能留在对应环带且不遮挡圈层标签，再决定改用分层明细页。
  - 若上述三段式节点仍无法保持可读，先拆成总览分布页与分层明细页；拆页方案需在逐字稿阶段确认。
  - 能力超过当前容量时，总览页保留代表性节点和完整分类逻辑；全部能力进入“能力 × 决策层级 × 判定依据 × 人工动作”原生矩阵明细页。

### Blocking decisions
- 自动化层级、十三项能力归类和工程要求均为示例内容；用于真实项目时必须由 EX-P09-01 至 EX-P09-04 替换，并完成跨角色确认。
```

## 反例：主题词代替完整逐字稿

```markdown
## P09 AI 赋能商品上架全流程

### Narrative role
- task：介绍 AI 上架能力。

### Information axis
- core claim：AI 能够提升上架效率和质量。
- complete on-slide copy：
  - 内容生成：自动生成标题和描述。
  - 质量校验：检查内容问题。
  - 业务价值：提效、提质、降本。
- concise speaker notes：现场补充具体能力和价值。

### Visual axis
- primary proof object：科技感能力分布图。
- page type and carrier：自定义。
- layout regions and reading order：中间放圆形，左右放卡片，底部放总结。
- focus and emphasis：标题和重点都用红色，要有冲击力。
- native editability and semantic groups：全部元素分组。
- capacity budget and overflow response：内容多时缩小字号。

### Blocking decisions
- 无。
```

- 标题、核心判断和“提效、提质、降本”没有证据支持，且使用了当前语言规范需要避免的泛化表达。
